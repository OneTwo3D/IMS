### Bulk actions on the sales-order list: allocate, advance status, batch-print packing slips (sales / UI)

- **New: tick orders on Sales > Orders and act on them together.** Each row has a checkbox, with select-all-on-page and a bar showing the selection count. **Allocate** and **Advance status** run, one order at a time, the very same services as the order page's Allocate and workflow buttons (same permission check, state machine, locks and refusals); **Print packing slips** opens one combined PDF of the selected orders drawn by the same renderer as the single slip (draft and cancelled orders are listed on a closing "Not printed" page).
- **Per-order results, never all-or-nothing.** A result panel lists each order as Done, Skipped (with the reason, e.g. "Already allocated" or "Not in a state that can advance") or Failed (with operator wording); one order failing does not stop the others. A request is capped at 100 orders;. Bulk Advance only reaches Processing, Allocated, Completed and Delivered, so it adds no storefront, warehouse or accounting write beyond what the single-order button already queues. No migration. Server actions `bulkAllocateSalesOrders` / `bulkAdvanceSalesOrders` require `sales.process`; the new `/api/packing-slips` route requires `sales`. The order page's workflow-button table moved to a shared module with no behaviour change. Help document: Sales.
