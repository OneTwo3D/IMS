### Mintsoft archive write for the owner's Archived decisions (first-load)
- `npm run first-load:mintsoft-archive -- ... --execute --plan-token <MSA-...> --env-file <ims.env> --expect-db <name> --expect-system-id <id> --operator <name>` now writes the reviewed plan to Mintsoft: for each product the owner set to Archived that would change, one at a time and paced, it re-reads the product and its live stock, sends the verified partial body `POST /api/Product {ID, SKU, DisCont: true}`, requires `Success: true` (HTTP 200 alone is not success), reads the product back and requires `DisCont` true with no other field changed, and stops at the first unexpected answer. Each attempt and verified (or failed) write is recorded in the IMS activity log with the SKU, the Mintsoft product id, the flag before and after and the operator, and a summary is printed.
- `--execute` runs only with the new ADMIN system switch `first_load_mintsoft_archive_enabled` on (default off) in the confirmed IMS target, the plan token of a freshly recomputed plan, decisions that would import, and proof that the import happened: every SKU to be written is an IMS product whose lifecycle is ARCHIVED in that target. The Mintsoft outbound-write grant (`MINTSOFT_WRITE_ALLOWED`) and the producer hold apply as to every Mintsoft write.
- The plan token now also covers the Mintsoft client id, the connection origin, whether a stock row exists and whether a real prepare is blocked. A product with no stock row is refused (`REFUSED_NO_STOCK_ROW`) instead of being read as stock 0. A VARIABLE parent is looked up in Mintsoft before it is skipped. The pre-rename hint also names letter-case and whitespace variants. The dry run exits 1 when a real prepare of the manifest is blocked.
- Registered as the writer-ownership row `mintsoft / product.discontinue` (P1 the owner by hand, P2 this operator command at step M), in writers-check (operator trigger, the new switch), in the producer census (`MINT_OPERATOR_TRANSPORT`) and in `settings:set`.
