### Customs clears: no lock across Mintsoft, and manual clears are now visible

- The clear sent to Mintsoft for a customs field emptied in IMS no longer holds a database row lock and transaction open across the Mintsoft request (a product save or refill could wait on it for up to half a minute, and a slow request could outlive the transaction). It now takes a short lease on the clear record, sends with nothing locked, then re-checks that the record is the same and the field still empty. A field filled again while the clear was in flight is not counted as cleared and the next run sends the filled value. A lease left by a dead run expires after 10 minutes.
- A customs description or country of origin that Mintsoft cannot clear through its API (and a commodity code whose clear failed five times) now raises an Open Discrepancy (category `CUSTOMS_CLEAR_MANUAL`) naming the field and the value Mintsoft still holds, only when that value is actually known; it resolves when Mintsoft shows the field empty or the IMS field is filled again. The old one-off, mislabelled "cannot clear" activity line is gone. The description's clear record now stays until Mintsoft shows it empty.
- "Nothing to update" from Mintsoft is no longer treated as a failure by itself: a read-back decides, and an already-empty field counts as cleared. A clear is retried at most five times.
- WooCommerce import: a parent's clear only clears a variation whose own native field is present and empty; a variation with no inheritance record is treated as inheriting only when its IMS value equals the parent's IMS value from before the import.
- Migration: adds `claimToken`, `claimedAt`, `attempts` and `unverifiedAttempts` to `product_customs_clears`, the `CUSTOMS_CLEAR_MANUAL` discrepancy category, and makes `products.customsInherited` NOT NULL (nulls become empty lists).
- A clear that is overtaken by a refill while its request is in flight no longer depends on a stored hash to recover: IMS re-reads the product and pushes its current values as a full update (last write wins at Mintsoft). Clear requests are built from a fresh read and time out after 2 minutes. Every clear Mintsoft answers (a refusal, an HTTP error status, or a read-back showing the value still set) counts toward the five-try cap; clears that get no answer or no proof (timeouts, network errors, failed read-backs) count toward a separate cap of twenty; past either cap the field becomes a manual-clear discrepancy. The recovery push after a superseded clear sends no clears. A manual-clear discrepancy is also resolved when the product is no longer eligible or not linked.
