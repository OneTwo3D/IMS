### WooCommerce sync: ended sales and unreserved on-hold orders (backend / sync, user-visible)

- **Fixed: an ended WooCommerce sale was never cleared in IMS.** An empty `sale_price` from WooCommerce (sale removed, or ended by its scheduled-sale cron) now clears `salePriceBase` for products and variations; before, the old value stayed and the next IMS save of the product pushed the expired discount back to the store. A payload that omits the field, or sends an unreadable value, still leaves IMS untouched.
- **Fixed: the absolute stock push erased WooCommerce's decrement for orders IMS had not reserved.** Before each push, IMS reads every `on-hold` and `processing` order in WooCommerce, plus `completed` orders modified since the order-sweep cursor minus one day (WooCommerce reduces stock for completed orders too), each walk ordered by id and proven complete (X-WP-Total before and after, strictly ascending ids). If completeness cannot be proven, or the cursor is missing, only forced-zero pushes are sent and the run reports it; the next run retries. Orders IMS has not imported are subtracted in full; an imported order still has its UNALLOCATED remainder subtracted, because the importer tolerates no or partial allocation (allocated or shipped quantity is taken from the order's allocation rows and shipment lines). Kit lines expand to their components. A variation id that matches no IMS product by id or SKU is never charged to its variable parent: that parent's variations are skipped for the run and an error is shown. If the orders cannot be read, the whole push is skipped and reported as an error (the 10,000-order safety ceiling counts as unproven too). Known accepted window: an order WooCommerce takes between the read and the write is not seen by that one push; the next push or the daily reconcile corrects it. No schema change.
