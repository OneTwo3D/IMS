### IMS-initiated refunds: Refund in WooCommerce operator task, and no duplicate credit note (sales / WooCommerce)

- **Added: a refund you record in IMS on a WooCommerce order raises ONE operator task, "Refund in WooCommerce"** (new operator-task reason `SHOP_REFUND_DUE`, on Sync > Exceptions, counted in the Exceptions banner), plus a **Refund to make in WooCommerce** badge on the order. The task gives the tax-inclusive amount, currency and credit note number, holds no personal data (the typed reason is not copied) and is raised once per refund, in the refund's own transaction. A person refunds the customer in WooCommerce; Done is for a refund that is not to be made.
- **IMS writes nothing to WooCommerce for these refunds:** no refund record, no status change, no order note, no money movement. A test locks that a refunded or partly refunded order never maps to a WooCommerce status.
- **Fixed: a later manual WooCommerce refund no longer raises a SECOND credit note, and an unrelated one is never swallowed.** The import deduplicated on the WooCommerce refund id alone, and the person's refund has a new id. IMS writes no marker to WooCommerce, so it cannot tell that refund from a separate one with the same amount. On an order with an open task the import therefore never links on its own: it records nothing and parks the refund (quarantined) with the figures. On the parked row a person chooses **Confirm this WooCommerce refund settles IMS refund (credit note)** (links the two, resolves the task and the row, raises no credit note, audited; same permission and fresh sign-in as recording a refund by hand) or records it as a separate refund as before. Orders with no open task are imported exactly as before.
- **Not built (filed as a follow-up): the optional `_ims_to_be_refunded` WooCommerce order meta.** It would be a live WooCommerce write path (outbound write hold, producer census); no setting and no write were added.
- **Migration:** adds one value to the operator-task reason enum (additive; no table or row is touched).
