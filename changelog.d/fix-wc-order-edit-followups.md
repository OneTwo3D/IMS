### WooCommerce order edits: follow-ups from the first review rounds (woocommerce)

Both switches (`wc_order_amendment_write_enabled`, `wc_order_amendment_unpaid_rewrite_enabled`) are still OFF by default; nothing changes until they are turned on. No migration.

- **Paid in WooCommerce, not yet in IMS: the task no longer says "collect the difference".** An order WooCommerce shows as paid (a paid date, an open paid-block, or a payment IMS holds that is not on the order's paid fields) that WooCommerce then changes gets the `WC_PAID_INCREASE` task worded for either outcome: *WooCommerce shows it paid at X; IMS holds Y. Check what the payment gateway charged. If it charged the new total, edit the IMS order to match. If it charged the old total, collect or refund the difference or undo the edit.* A REDUCTION (fewer units, a lower unit price) on such an order now raises the same task instead of being left on the list as "order not paid". An order paid in IMS keeps the original wording.
- **After an IMS edit, WooCommerce's price, shipping and discount are no longer skipped quietly.** An unpaid order edited in IMS that now differs from WooCommerce in a unit price, shipping or discount (the quantity baseline cannot attribute these) is refused visibly (Sync > Exceptions); a tax or total difference alone, or quantities WooCommerce has not changed, stay quiet. On a paid order the latest-edit-wins rule now also covers an added item (counts only if the baseline did not show it) and a higher unit price (no baseline: after an IMS edit it raises no false increase task).
- **Rewrite hardening.** A line whose total is above its subtotal is refused (it would be stored with disagreeing figures); with no shipping line on the payload the shipping method fields are cleared; the importer's mapping now runs before the row-lock transaction (fewer connections held, shorter lock) and a changed booked rate is a retry; the header tax rate is locked with the importer's own `allowMissing` rule; the pegs ended by a product change are logged as a product change, not as a removed line.
- **Recheck drain (o3d-hu8g9).** One drain at a time (a try-lock; the sweep and a manual reconcile no longer read the same rows); a read past its deadline is aborted, not abandoned; the 48-failed-read cap also waits until the row is 72 hours old (fast-failing reads no longer drop every row after two days); a drain that fails is reported as a `warnings` entry on the sweep's result. The budget is checked before each new read (a comparison already running is not interrupted): the wording now says so.
- **Not changed, on purpose.** An authorised-but-uncaptured payment (a transaction id, no paid date) is not treated as paid: the importer reads a payment from the paid date only, so doing otherwise here would disagree with it. Whether the Woo PDF-invoice plugin numbers invoices at order creation (which would make the invoice-number refusal block nearly every order) is an owner check, still open. The drain is not wrapped in a `finally` for a throwing cursor commit (optional: the next sweep drains).
- **Docs and tests.** `help-docs/woocommerce.md` (the refusal list no longer names a currency refusal that never fires: an order in another currency is not compared at all; the garbled paid-order sentence is rewritten; what reopens after an IMS edit is stated) and `help-docs/warehouse.md` (the paid-order task). New unit tests (under-lock paid checks, the FAILED paid-block, the added-item line, drain single flight, abort and budget) and scratch-database tests (task wording, the reduction, held-invoice-only, both refusal resolves, the peg end, two order-lock races).
