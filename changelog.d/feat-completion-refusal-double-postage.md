### Refused WooCommerce completions and double postage on merged orders now show on Sync > Exceptions (backend / sync / UI)

- **New: a WooCommerce completion IMS permanently refuses now raises a row on Sync > Exceptions.** When the store marks an order completed and IMS refuses to turn that into shipments because the shipment lines do not cover what was ordered (a coverage shortfall), the delivery is acknowledged and nothing brings the order back, so until now the only record was a passive activity row. It is now a quarantined `shopping_sync_logs` row on the order (new row family `WC_COMPLETION_REFUSAL`, no migration), listed under **WooCommerce orders - completed in the store but not fulfilled in IMS** and counted in the Exceptions banner. One open row per order (a redelivery refreshes it). It clears by itself when the completion later succeeds, the store no longer says completed, or the order is shipped, completed, delivered or cancelled by any route; there is nothing to acknowledge. The retention sweep never deletes an open row; a cleared one expires like any other. The store later sending a non-completed status closes it only when that event is strictly newer than the refusing one (an older event delivered late does not). A refusal whose row cannot be written is reported as a retryable failure so the delivery is redelivered. A transient refusal (backorder, no stock) still retries through the webhook inbox and raises no row.
- **New: a possible double postage on a merged order is flagged for an IMS operator.** When Mintsoft merges orders and more than one live order of the merge charged the customer shipping above zero, the absorbed order shows under **Merged orders - possible double postage** on Sync > Exceptions, naming the orders and amounts. IMS never refunds automatically, writes no Mintsoft comment and raises no warehouse task (no warehouse action is needed). An operator checks, refunds by hand if due, then presses **Clear**, which needs the sync permission and a fresh sign-in and is recorded in the activity log with who cleared it. Additive migration: two nullable columns on `wms_order_push_links` (`double_postage_at`, `double_postage_detail`). Help documents: WooCommerce, Warehouse (Mintsoft).
