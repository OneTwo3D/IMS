### Accounting fixes: unmapped stock adjustments, reverse-charge sales invoices, unbalanced journals

- A valued stock adjustment with no reason, a reason with no account, or no inventory account mapped used to change the cost layers and post nothing. It now still commits, and an outstanding-posting row appears in the exception inbox (kind: stock adjustment journal) so the journal can be posted by hand. The row is recorded only when a mapped adjustment would have posted: nothing is reported when no accounting connector is active, Xero sync is off, or the inventory-adjustment sync type is off. A stock import (CSV) has no reason column, so each valued row in it creates one of these outstanding rows; that is intended, so the gap is visible.
- A native sales invoice for an order with a reverse-charge sales line is refused when the reverse-charge sales tax type is empty, with a message naming the setting, instead of posting on the line's taxable code. WooCommerce order import is unchanged.
- A journal whose lines, rounded to the penny as they are sent to Xero, differ by a penny is refused before it is queued (shown as an owed posting) instead of failing at Xero. A disabled sync or sync type still owes nothing.
