### First-load tool
- Changed (owner ruling 2026-11-21, "Use Woo's status as gospel"): the IMS lifecycle is DERIVED FROM WOOCOMMERCE wherever the first load can see a WooCommerce status: a joined variation (VARIANT, or a KIT/BOM variation) uses its own `variationStatus`, a simple, KIT or BOM product uses `woo-products` `status`. Woo private, draft or pending loads as DRAFT; publish loads as ACTIVE, except that a Qoblex Inactive (EOL) stays EOL (EOL still pushes publish). This overrides the Qoblex State, Archived included; a product with no Woo status keeps the Qoblex lifecycle. Every changed SKU is an INFO `LIFECYCLE_TAKEN_FROM_WOO` (SKU, Qoblex state, Woo status, result) with a per-run `LIFECYCLE_TAKEN_FROM_WOO_COUNT`. The blocking `LIFECYCLE_PUSH_WOULD_CHANGE_WOO_STATUS` and the `LIFECYCLE_DISAGREES_WITH_WOO` / `STALE_LIFECYCLE_CONFIRMATION` warnings are gone (a push writes back the status the lifecycle was taken from, so it cannot change it); `lifecycle-confirmations` is obsolete and every row is an INFO no-op. `variant-parents` gains a `variationStatus` column (written by `first-load:woo-snapshot`); a blank one is refused (`MISSING_VARIATION_STATUS`), and a `variant-parents.csv` from a snapshot taken before the column existed is refused with a message saying so. `woo-products` gains an optional `status` column; a listed product with no usable status is the warning `LIFECYCLE_WOO_STATUS_UNUSABLE` (previously only DRAFT products were listed); an absent status column means no warning of that kind. In the real load there is no `woo-products` file, so simple, KIT and BOM products keep the Qoblex lifecycle and the run warns `LIFECYCLE_NOT_FROM_WOO` with the count (a later IMS to WooCommerce push may change their WooCommerce status). WooCommerce private and pending are unpublished and a push writes them back as draft.
- Fixed: `non-stock-skus` fills the kind only when the source cell is blank, `Unknown` or non-inventory; a SKU whose source states another type (simple, variable, kit, bom, ...) is refused as `NON_STOCK_DECISION_CONFLICT` (not for a row a State or ghost rule skips) instead of losing its stock silently. A nonzero quantity ignored on a non-stock SKU is reported once, in the stock lots, as INFO `NON_STOCK_QTY_IGNORED`.
- Fixed: `sku-renames` refuses a rename whose `fromSku` or `toSku` is on `sku-exclusions` (`RENAME_FROM_EXCLUDED` / `RENAME_TO_EXCLUDED`) instead of silently loading an excluded product.
