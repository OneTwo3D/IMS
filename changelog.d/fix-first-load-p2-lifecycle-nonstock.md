### First-load tool
- Fixed: the lifecycle check now fires on Qoblex data and compares the right status. Nothing is pushed to WooCommerce at load time, but a later IMS to WooCommerce push writes each variation's (and simple product's) OWN status from its lifecycle (DRAFT writes draft, ACTIVE and EOL write publish). Every joined VARIANT, KIT or BOM variation is compared with its own WooCommerce status; one a push would change (DRAFT against publish, ACTIVE or EOL against draft, pending or private) is a blocking ERROR `LIFECYCLE_PUSH_WOULD_CHANGE_WOO_STATUS` unless confirmed on the new `lifecycle-confirmations` decision list (`sku,reason`; INFO `LIFECYCLE_CONFIRMED`). A DRAFT variation published under an unpublished parent warns `LIFECYCLE_DISAGREES_WITH_WOO`. `variant-parents` gains a `variationStatus` column (written by `first-load:woo-snapshot`; a snapshot taken before this change must be taken again) and `woo-products` an optional `status` column for the same check on simple, KIT and BOM products.
- Fixed: `non-stock-skus` fills the kind only when the source cell is blank, `Unknown` or non-inventory; a SKU whose source states another type (simple, variable, kit, bom, ...) is refused as `NON_STOCK_DECISION_CONFLICT` (not for a row a State or ghost rule skips) instead of losing its stock silently. A nonzero quantity ignored on a non-stock SKU is reported once, in the stock lots, as INFO `NON_STOCK_QTY_IGNORED`.
- Fixed: `sku-renames` refuses a rename whose `fromSku` or `toSku` is on `sku-exclusions` (`RENAME_FROM_EXCLUDED` / `RENAME_TO_EXCLUDED`) instead of silently loading an excluded product.
