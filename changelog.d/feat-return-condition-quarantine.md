### Condition check on returns: unsellable returns go to a quarantine warehouse (inventory)
Built, switched off: new ADMIN system switch `return_condition_check_enabled` (default off; `npm run settings:set ... --confirm-admin`, status and a list of unclean quarantine warehouses on Settings > Sales). With it off, nothing changes. FRS 102 s13.4 (lower of cost and estimated selling price), part 2 of the stock write-down work after the slow-stock report.

- **Quarantine warehouse.** The existing warehouse type **Quarantine** (`Warehouse.type = QUARANTINE`, no schema change and no migration) now means "stock not sellable" while the switch is on: never allocated (automatic allocation, manual allocation and moving an allocation into it), never counted as available (product list and page, dashboard stock tiles, sales statistics, reorder planning), never pushed to WooCommerce, not usable for a production order, and never the storefront import's default warehouse. Warehouse settings refuse a quarantine warehouse marked available for sale, sync to store or default; a Mintsoft binding to one is refused.
- **Condition at restock.** The refund dialog (when it returns stock) asks for **Sellable** or **Unsellable**: unsellable must go to a quarantine warehouse and sellable to an ordinary one, otherwise the restock is refused and nothing is written. An unsellable return of units shipped from a WMS-bound warehouse (or of an order with a SYNCED warehouse push link) is refused, because quarantine is IMS-only and the 3PL would count the unit again. The Mintsoft returns inbox restock asks for the condition too but restocks only **Sellable** units (an unsellable unit is at the 3PL: handle it there). The stock comes back exactly as before, at its return cost layer and with the same journals; only the warehouse differs. The condition is recorded in the activity log (and the returns inbox resolution note). Storefront refunds state no condition and restock to the default return warehouse as before.
- **Review.** Write-off is a stock adjustment in the quarantine warehouse with a reason mapped to a write-off account; return to stock is a transfer to a sellable warehouse (FIFO layers move at their cost). Documented in help-docs (Stock Control, Quarantine: unsellable returns).
- **Reports.** The product page marks a quarantine warehouse; Slow Stock marks quarantine units on each row, adds a notice, and its CSV adds a `quarantineQty` column only when some row holds quarantine stock. Every stock report can be filtered to the quarantine warehouse.
- **Review round 1.** The Mintsoft returns-inbox restock refuses an unsellable unit (quarantine is IMS-only and the unit is at the 3PL, where alignment would count it a second time). Forecasts, the reorder inventory list and reorder purchase/production orders leave quarantine out. A warehouse cannot be changed to Quarantine while it has a WMS binding, open allocations, unshipped shipments or open production orders, and an allocation in quarantine cannot be increased. The switch is an ADMIN command-line switch instead of a settings toggle. The refund dialog refuses an unsellable return of units shipped from a WMS-bound warehouse or an order the WMS holds (round 2). A parked storefront refund recorded by hand restocks as the automatic storefront route does (documented exception, owner ruling). The DB test fixture carries its own mapped tax rate and isolates leaked accounting settings.
