### Exchanges inside a return (sales / returns / UI / analytics)

- **New: record an exchange while a return is recorded.** With the new setting `return_exchange_enabled` on (Settings > Sales, **off by default**), the refund dialog can pick replacement items, quantity and price. The return side is unchanged (refund lines, stock back, cost reversal, credit note). The replacement items are added as **new lines on the same order**, each linked to the refund it replaces (`sales_order_lines.exchange_for_refund_id`, additive nullable column with an index and a set-null foreign key, migration `20261118090000_sales_order_line_exchange_for_refund`), in the refund's own transaction: they are then reserved, shipped and invoiced by the normal flow, and the posted invoice's update is queued through the existing path and its producer-side hold (held means a shadow is recorded and nothing is sent). The order page marks them *Replaces <credit note>* and the Refunds section recaps the exchange.
- **Money is shown, never moved.** The credit note and the replacement net off, so an even exchange moves no money in IMS. A difference is shown as *Customer owes X* or *Refund X*; IMS charges nothing and refunds nothing for it (use the existing payment and refund actions). A replacement that would leave the order fully refunded is refused (a fully refunded order holds no demand, so the replacement could not ship).
- **Only where IMS can add lines.** The exchange reuses the confirmed-order edit gates (a dispatched order, a picked or packed shipment, an unposted invoice, a warehouse that can no longer amend its order, ...) with the refund-related blocks lifted, and refuses a draft, a fully refunded order and an order the daily batch booked ahead of dispatch. New read-only actions `getReturnExchangeOffer` and `previewReturnExchange` feed the dialog; `createRefund` takes an `exchange` option (operator only; needs the refund, edit and process permissions).
- **WooCommerce.** IMS adds no lines in WooCommerce. An order with a shop link needs the same acknowledgement as editing it (exactly `true`), is marked edited in IMS and keeps its WooCommerce line baseline; the IMS refund raises the usual *Refund in WooCommerce* task.
- **Refund delete.** A refund that came with an exchange refuses deletion (new refusal `exchange_refund`).
- **Analytics.** The Returns report shows exchanges apart: Exchanged units, Exchanged refund value, Lost refund value (the credit not exchanged), Return rate excluding exchanges, Replacement qty; the credit is not read as a lost sale. CSV export carries the new columns.
- Help documents: Sales (*Exchanges inside a return*), Analytics.
