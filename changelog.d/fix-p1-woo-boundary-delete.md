### WooCommerce stock sync: order delete and transaction reset safety (Stock sync)

- **Fixed: deleting an order, or releasing or reducing its allocation (cancel, deallocate, refund trim, manual reduce or move, re-allocation, over-allocation rebalance), no longer lets a stock push restore units WooCommerce already sold.** The order is recorded (with its WooCommerce order id, captured before a delete removes the link) in the same transaction, and every stock push re-fetches the recorded orders from WooCommerce by id and charges the ones still completed or held. The completed-history boundary keeps bounding the bulk read, so large stores keep pushing. A record is cleared only once WooCommerce no longer holds the order or IMS accounts for it again; if a recorded order cannot be fetched, positive pushes wait for that run. Normal shipping records nothing.
- **Fixed: a transaction reset now also clears the WooCommerce cancellation backstop cursor and backfill state**, so the next backstop run backfills from the start instead of resuming from the old cursor.
