### WooCommerce stock sync: order delete and transaction reset safety (Stock sync)

- **Fixed: deleting an order, or releasing or reducing its allocation (cancel, deallocate, refund trim, manual reduce or move, re-allocation, over-allocation rebalance), no longer lets a stock push restore units WooCommerce already sold.** The order is recorded (with its WooCommerce order id, captured before a delete removes the link) in the same transaction, and every stock push charges the recorded orders that WooCommerce still holds (a rotating slice is re-read by id each run, the rest are charged from what the last read showed, so a large set never blocks). Records are bound to the WooCommerce connection: a save to a different store retires them; a same-store key rotation or a product-id cache reset keeps them. The completed-history boundary keeps bounding the bulk read, so large stores keep pushing. A record is cleared only once WooCommerce no longer holds the order or IMS accounts for it again; if a recorded order has never been read and cannot be, positive pushes wait for that run. Normal shipping records nothing.
- **Fixed: a transaction reset now also clears the WooCommerce cancellation backstop cursor and backfill state**, so the next backstop run backfills from the start instead of resuming from the old cursor.
