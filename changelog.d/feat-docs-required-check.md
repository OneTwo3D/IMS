### Documentation updates are mandatory with code changes (dev workflow)
- New CI check `docs-required` (`npm run check:docs-required`, ungated job in `.github/workflows/static-guards.yml`, also in `npm run validate` and `check:all`): a PR that changes behaviour-bearing code (`app/`, `lib/`, `components/`, `prisma/schema.prisma`, `prisma/migrations/`, shipped `scripts/`, `deploy/`, `proxy.ts`, `next.config.ts`, `instrumentation*.ts`) fails unless it also changes `docs/`, `help-docs/`, `README.md` or `deploy/README.md`. Test files, `*.d.ts`, Markdown, `lib/releases.ts` and repo tooling under `scripts/` are excluded; plans and notes under `docs/scratch|todo|completed|archive` do not count as docs. It compares against the merge base, like the migration-conventions check.
- Opt-out: a line `Docs: none — <reason>` (20+ characters) added to the PR's changelog.d fragment. A bare or placeholder reason fails; the check prints every reason it accepted.
- The rule (code is the source of truth; fix the doc, or file a bead when the code looks wrong) is in `CLAUDE.md`, `AGENTS.md`, `docs/development.md`, `docs/agent-workflow.md` and the PR template.
