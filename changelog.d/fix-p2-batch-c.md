### WooCommerce reconcile cadence, buried product recovery, liveness alarm bounds (sync)
- The WooCommerce daily reconcile (orders, products, stock) in webhook-primary mode now runs when a day, less one hour of slack, has passed since its last stamp. A daily cron that started seconds short of 24 hours used to skip, so the effective cadence could be 48 hours.
- Products the bulk product sync could not import for a reason no retry fixes (duplicate GTIN, id mapped to another product, structure conflict, too many variations) are now remembered, up to 200. Each product sync run fetches up to 20 of them directly by id, least recently tried first, and imports any whose conflict you have since fixed in IMS, with no re-save in WooCommerce. A run that left some out says how many in the activity log.
- The read-sync liveness alarm now reads its inputs and breach stamps inside a bounded transaction with a server-side statement timeout, so a stalled database read fails the job visibly instead of leaving it waiting.
