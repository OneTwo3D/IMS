### Draft sales orders can now be edited (sales)

- **New: Edit order on a Draft sales order.** The order page has an **Edit order** button that opens the new-order form pre-filled (customer, addresses, lines, quantities, prices, discounts, shipping, VAT basis, warehouse, delivery date, notes). Saving replaces the lines and re-prices the order in one transaction, keeping the order number, status and history; the activity log records the edit with the old and new totals. Previously the only way to fix a typo or add an item was Cancel and re-create.
- **Refused, with the reason shown on the disabled button:** any order that is not a Draft, and a draft that has stock allocated, a shipment, a posted accounting invoice, a warehouse push, a refund or return expectation, or a WooCommerce link (a webhook could overwrite the edit). The server re-checks all of it under the order lock, and refuses a save when the order changed since the form was opened (reload and retry). Editing a **confirmed** order (it needs the invoice-update path, reallocation and a warehouse amendment, plus a desync warning for WooCommerce orders) is not available yet and is tracked separately. Nothing is sent to the accounting system, the warehouse or the store by an edit.
- **Internal: `createSalesOrder` and the new `updateSalesOrder` share one pure money builder** (`buildSalesOrderWriteModel`: FX, per-line tax, discount, shipping tax, totals), so an edited draft is priced by the same arithmetic as a fresh one. Create's written rows are unchanged, pinned byte-for-byte against rows captured before the extraction.
- **Docs:** the sales help page no longer implies a general sales-order edit exists; it documents editing a draft and what is not yet editable.
