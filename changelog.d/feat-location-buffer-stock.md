### Buffer stock per warehouse: hold units back from WooCommerce (inventory / sync / UI)

- **New: a per-warehouse channel buffer on the product page.** On a simple, variant or BOM product, **Channel buffer by warehouse** holds N units back at a warehouse so they never reach the store. What WooCommerce is told for a warehouse is `max(0, on hand - reserved - buffer)`, then the warehouses are summed (kit availability is built from the components' buffered figures). It is applied in exactly one place, the stock-push availability computation, so IMS's own on-hand, reserved and allocatable figures are unchanged, IMS order allocation may still use buffered units, and the Mintsoft stock alignment pass keeps reconciling real on-hand (the buffer applies only to the channel push, after alignment). With every buffer at 0 (the default for every existing row) the pushed quantities and payloads are identical to before.
- **Editing needs inventory edit and a reason.** Each change writes an activity-log entry in the same transaction (who, when, old value, new value, required reason; entity type product, so the reason is operator text outside the erasure scope) and queues the normal stock push for that product through the existing enqueue path; no new outbound producer.
- Additive migration `20261117040000_stock_level_buffer_qty`: `stock_levels."bufferQty"` `DECIMAL(14,6) NOT NULL DEFAULT 0` with a non-negative CHECK. Help documents: Inventory, WooCommerce.
