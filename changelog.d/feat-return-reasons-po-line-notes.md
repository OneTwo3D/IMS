### Return reasons and internal notes on PO lines (sales / purchasing / settings)

- **New: return reasons.** A configurable list in Settings > Inventory (name, sort order, active flag, like the stock adjustment reasons; Settings permission; names unique ignoring case; a reason that refunds use cannot be deleted, set it inactive instead). One optional reason per refund (`sales_order_refunds.return_reason_id`), chosen in the refund dialog. Per refund rather than per line, because the refund is the unit WooCommerce states a reason for. The free-text refund reason is unchanged and still required in the dialog.
- **New: returns by reason.** The Returns analytics page gains a By return reason table: refund count, returned quantity and credit value per reason (basis rules as the main report), refunds with no reason as Unspecified.
- **New: WooCommerce mapping.** An imported refund's reason text maps to a return reason only when it equals an active reason's name ignoring case; otherwise the reason stays empty. Reasons are never created automatically.
- **New: internal notes on PO lines.** One nullable `purchase_order_lines.notes` column; a notepad on the PO form and on the PO page line, saved with the order (and by a separate Save note on the PO page for any status). Notes are internal: not on the supplier PO PDF, not in the supplier email, not in the supplier portal; tests pin it. 2,000 character cap.
- **Erasure and first load:** return reasons are configuration (names are not personal), so the table is `CONFIG_ALLOWED` for first load and carries no erasure entry; the refund's `return_reason_id` is classified not-personal. PO line notes sit on a supplier document outside the customer/order erasure census, so they carry no erasure entry and need no free-text guard.
- Two additive migrations: `20261117150000_return_reasons` (new table, nullable foreign key on refunds, `ON DELETE SET NULL`) and `20261117150100_po_line_notes` (one nullable column). Help documents: Sales, Purchasing, Settings, Analytics.
