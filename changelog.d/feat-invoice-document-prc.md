### Customer invoice in My Account: switchover runbook, credit note download, on-demand fetch for historic orders, invoice e-mail (backend / WooCommerce / Xero)

- **Switched off, no behaviour change until configured.** Nothing here writes to Xero. Everything written to WooCommerce still goes through the existing outbox, hold and the switch `wc_invoice_document_enabled` (default off).
- **New: a customer's credit note has its own download.** `POST /api/shopping/woocommerce/credit-note-pdf` is the invoice download's twin: same signature, one-time nonce and order-ownership proof, plus the storefront's refund id. The refund is looked up inside the proved order, so a refund of another customer's order is refused, never served. It needs `invoice_documents_credit_notes_enabled`.
- **Changed: historic orders are queued on the first click, not fetched inline.** With `invoice_documents_lazy_fetch_enabled` on, the first customer click on an order IMS holds no invoice for answers HTTP 202 "preparing" (`retryAfterSeconds`, `Retry-After`) and queues one read-only Xero fetch; the `invoice-documents` cron does it (a few per run, even with no sweep floor), and a later click is served the PDF. A customer can only start this from the storefront once the WooCommerce helper plugin shows its button (and accepts the request) for orders without the `_ims_invoice_pdf_available` flag; the shipped plugin does not, so until that plugin change is deployed the queue is reachable only by a signed request. With no sweep floor the cron still rechecks due documents (a queued credit note included), because the floor only limits new unsolicited fetches. The queue is de-duplicated (one fetch per document however many clicks), capped per day (`invoice_documents_lazy_daily_cap`, default 200) and in total waiting (`invoice_documents_lazy_outstanding_cap`, default 200), so it fits the shared 5,000-a-day Xero allowance; past a cap the answer is 429 with `Retry-After`. No bulk backfill. Additive migration: one nullable column and an index on `invoice_document_fetch_states`.
- **Changed: the invoice e-mail attaches the stored Xero PDF when `wc_invoice_document_enabled` is on.** Off (the default), it attaches the invoice IMS renders itself, exactly as before. On, a stored document IMS cannot serve right now holds the e-mail back instead of sending a different rendering.
- **New: switchover runbook** (`docs/ops/invoice-documents-switchover-runbook.md`): IMS live first, the old invoice plugin off right after (the duplicate button for a short while is accepted), verification, and rollback (turn the setting off, clear the order meta). Fixed the plugin's name in the runbooks and help (it is the onetwoInventory Helper, not `wc-invoice-handoff`) and the invoice PDF secret wording (its own secret, not the webhook secret).
- **New: helper-plugin contract test** (`tests/connectors/woo-helper-invoice-contract.test.ts`, fixture `tests/fixtures/woo-helper-invoice-contract.json`): the order meta the plugin reads, the signed request it sends and the answers it can get, pinned against the plugin source and against what IMS writes and answers. The plugin is not changed.
- Help documents: WooCommerce, Documents & Email, Xero Sync, Settings.
