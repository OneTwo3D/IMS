### Confirmed sales orders can be edited, after a WooCommerce-desync warning (sales / UI / backend)

- **New: edit a confirmed sales order.** Owner ruling: drafts are editable; a confirmed order is editable only after a warning that the edit desyncs it from WooCommerce; after dispatch only addresses and notes are editable. **Edit order** now works from Pending Payment up to dispatch. The edit is one transaction under the order lock and reuses the create path's line, tax, FX and total builder (no second pricing path): it releases the order's stock reservations, replaces the lines, recomputes the totals (the order keeps its booked currency and exchange rate), reserves stock again, and queues an update of the posted accounting invoice through the existing invoice-update path (under the outbound write hold the update is recorded as a shadow and nothing is queued). The order's `updatedAt` moves, which makes a pushed, not-yet-picked order a warehouse amendment candidate; IMS writes no warehouse comment. A failed re-reservation, an invoice that no longer reconciles, or a refused queue rolls the whole edit back. An audit entry (written in the same transaction) and an activity row record each edit.
- **New: the desync warning.** An order with a WooCommerce link asks for confirmation in the form ("this edit will not reach WooCommerce; WooCommerce keeps the original"), and `updateSalesOrder` refuses unless it is called with `acknowledgeShopDesync: true`. A manual order needs no acknowledgement.
- **New: after dispatch, addresses and notes only.** A shipped, completed or partly shipped order offers **Edit addresses & notes** (new action `updateSalesOrderAddressesAndNotes`, same acknowledgement for shop orders); its lines stay closed (use a refund). Cancelled, delivered (closed) and erased orders cannot be edited. Still refused whatever the status: refunds or return expectations against the lines, a picked or packed shipment, an invoice queued but not yet posted, an order the warehouse is already picking, shop fee lines. A paid or store-credited confirmed order may be edited only if its total and currency stay the same.
- **Changed: the WooCommerce update path no longer overwrites an order edited in IMS (policy b).** An order edited here is marked (`sales_orders.edited_in_ims_at`, additive nullable column, migration `20261117210000_sales_order_edited_in_ims`); a later order.updated delivery then leaves its addresses, notes and shipping label alone and raises no "edited in WooCommerce after import" row, while the order number, the VAT number and the paid state still mirror. Orders never edited here behave exactly as before; the refund and status-echo paths are untouched.
- **Fixed (review round 1): an edit keeps the WooCommerce line ids.** The edit now updates the lines it continues in place (the form sends each line's saved id; a line without one continues the saved line of the same product), deletes only removed lines and creates only added ones, so `external_line_item_id` survives and a later itemised WooCommerce refund still links to its line (stock return and cost reversal as before). A refund that returns quantity of a line the edit removed is QUARANTINED on an order edited in IMS (nothing recorded or sent, the money was already returned in the shop) instead of being written unlinked.
- **Fixed (review round 1): the posted-invoice update is never silently skipped.** After queueing the update the edit requires an explicit outcome (queued, held as a shadow, or not configured to post); when the helper declines without asking the queue (the invoice or chart belongs to another accounting connector than the active one, or the connector cannot update invoices) the whole edit rolls back and the operator is told nothing was changed. The post-commit "invoice not queued" warning is gone with the case it described.
- **Fixed (review round 1): the warehouse must still be able to amend the order.** Before a line edit of an order already pushed to the warehouse (and before an address or notes edit of one not yet dispatched) IMS asks the same gate the amendment pass uses (new read-only connector method `probeOrderAmendable`, the order is found, is this order, is not merged and is still NEW). When it is not amendable, or cannot be read, the edit is refused with `AMENDMENT_NOT_APPLIED` and nothing is changed; an order with no warehouse order yet is unaffected.
- **Fixed (review round 2): the storefront stock sync covers products the edit removed** (the released reservations' products are unioned with the re-reservation's).
- **Fixed (review round 2): WooCommerce line changes stay visible after an IMS edit.** The first IMS line edit of a shop order stores the WooCommerce-facing lines and total as they were (`sales_orders.wc_line_baseline`, additive nullable JSON, in the same migration); the *edited in WooCommerce after import* comparison then runs against that baseline instead of being switched off, so the IMS edit raises nothing and a later WooCommerce change does. An address or notes edit takes no baseline and suppresses nothing.
- Help documents: Sales (*Editing an order*, *Orders that already have an accounting invoice*), WooCommerce.
