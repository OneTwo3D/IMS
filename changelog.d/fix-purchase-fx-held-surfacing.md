### Per-event FX rates for purchasing: orders still owed a held catch-up are listed, and caught up in one command
- Still behind `purchase_event_fx_rates_enabled` (off) and its interlock (still off); with the switch off nothing changes.
- Every dry run of `npm run purchase-fx:reconcile` now starts with a "held catch-up owed" banner: the orders with a held journal of a bill posted outside IMS (`held_since` set), each with what it is owed now, or that a bill is still held, already stale, or would go stale now (the connected organisation is not the one it was confirmed on: reconnect the right one before any `--apply`). An order that cannot be checked is shown as "banner incomplete"; the dry run goes on. The banner is not shown with `--held`.
- `npm run purchase-fx:reconcile -- --held --apply` catches up exactly those orders after the same Xero organisation is connected again (`--held` alone is a dry run; refused together with `--po`). It is refused while no Xero organisation is connected, while an order cannot be checked, and while a held bill would go stale through a different organisation, unless `--accept-stale` is given.
- A failed order in `purchase-fx:reconcile` no longer claims nothing was written: the run may have committed before the error, so check the order.
- Corrected the wording: reconnecting Xero does not catch a held journal up by itself; the next receipt or return of the order, another bill's change, or a reconcile run does. A confirmation goes stale if any reconciliation of the order runs while a different organisation is connected. A credit note against such a bill uses the IMS bill's booked rate.
