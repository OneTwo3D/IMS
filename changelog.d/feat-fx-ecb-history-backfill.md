### One-off operator command: backfill historical ECB exchange rates (first load)
- New `npm run fx:backfill-ecb` loads historical ECB reference rates from a hand-downloaded `eurofxref-hist.csv` into `fx_rates` (never fetches), so the first load can price old foreign purchase orders and stock lots. Rates are converted to the organisation's base currency (`X_per_EUR / BASE_per_EUR`, 8 dp), written for the enabled foreign currencies one row per ECB business day with `source = 'ecb-history'` and `fetchedAt` at 16:00 Europe/Berlin (DST-correct) in UTC.
- It writes only BEFORE the live period: under the FX table lock it refuses (exit 4, days listed, nothing written) any planned day on or after a currency's first live/manual/Aelia row or on or after the start of the Aelia period, so a backfilled row can never become the latest row, un-pin a manual rate, fill a live gap or tie a live rate. Re-running skips the `ecb-history` rows already written. Blank/N/A cells, a window outside the file or a missing base also refuse; `--dry-run` prints counts only.
- A real run is one transaction behind the same env-file, `--expect-db` and `--expect-system-id` confirmation as `first-load:apply` (checked before the lock is taken; 30 s lock timeout; a failed COMMIT reports an unknown outcome). No schema change.
- Docs: `docs/first-load-input-spec.md` (ims-fx-rates) and `docs/installation.md` (First load).
