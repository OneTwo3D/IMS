### Audited command line for system-managed switches (ops)
- **`npm run settings:get -- --key <k>`** (read only) prints a switch's stored value, effective value, default, and the last audit entry with who wrote it.
- **`npm run settings:set -- --key <k> --value <v> --by <name> --reason "<text>" [--yes] [--confirm-admin]`** replaces the raw SQL method for switches with no settings screen. Dry run by default; with `--yes` it upserts the `settings` row, writes an activity-log entry (who, why, old, new) and reads the value back in one transaction.
- Allowlist of 14 switches (the 11 on development plus the three Mintsoft supplier switches from #1065), validated as their readers read them (exact `true`/`false`, or `off`/`flag` for `wms_merge_candidate_mode`). Credential settings and unlisted keys are refused. `mintsoft_parent_sku_delete_enabled` needs product parity on, and `wms_merge_hold_enabled` needs flag mode.
- The three Mintsoft supplier switches (`mintsoft_supplier_create_enabled`, `mintsoft_asn_send_supplier_enabled`, `mintsoft_asn_supplier_required`) are ADMIN with a fresh sign-in in the screen. The CLI assumes ADMIN authority from shell access, writes one only with `--yes --confirm-admin`, and records the operator and that assumption in a WARNING-level audit entry. `mintsoft_asn_supplier_required` needs `mintsoft_asn_send_supplier_enabled` on, which cannot be turned off while it is on. The switchover runbook now uses this command instead of raw SQL. `storefront_customer_email_enabled` is added once #1062 merges.
