### Condition check on returns: what must be true before the switch goes on (inventory)
Follow-ups to the condition check on returns (`return_condition_check_enabled`, ADMIN switch, still off by default). With the switch off nothing changes, with one deliberate exception noted below.

- **Turn-on interlock.** `npm run settings:set -- --key return_condition_check_enabled --value true ...` is refused while any quarantine warehouse still looks sellable: a sellable flag (available for sale, sync to store, default, default return warehouse, available in purchase orders) or sellable work pointing at it (a warehouse-system binding, open allocations, unshipped shipments, open production orders, transfers in transit into it, purchase orders still to be received there). Checked in the dry run and again inside the write transaction. Settings > Sales lists the same issues.
- **Type changes.** Changing a warehouse to Quarantine is refused while it carries that sellable work, **whatever the switch** (the one change with the switch off: the type means nothing yet, but turning the switch on later would strand the work). With the switch on, changing a quarantine warehouse to another type is refused while it holds stock; the message names the write-off (stock adjustment) and transfer routes. Both are checked under a lock on the warehouse row; manual allocation re-checks the type under the same row lock.
- **Warehouse flags.** With the switch on, a quarantine warehouse may also not be the default return warehouse (storefront refunds restock there without a condition) or available for purchase orders (it takes only returns and transfers).
- **Production.** A production order in a quarantine warehouse cannot be started or completed while the switch is on (it can still be cancelled).
- **Returns in transit.** With `refund_returns_in_transit_enabled` also on, the refund dialog asks and records no condition (the parcel's restock from the returns inbox asks it), offers no quarantine warehouse, and refuses a quarantine expected warehouse.
- **3PL returns.** An unsellable return at the 3PL (returns inbox, or a refund of units shipped from a WMS-bound warehouse) is still refused; the message and docs now give the route: restock it as Sellable into the bound warehouse (which clears a refund's Stock in Transit), have the 3PL write it off or hold it, then write it off in IMS with a stock adjustment. No separate in-transit write-off was built.
- **Reports.** The Analytics stock-on-hand and stock-allocation tables and the Stock on Hand report show 0 available for quarantine rows.
