### WooCommerce inbound import fixes (woocommerce)
- Webhook inbox: each event is claimed with its own clock, so an event claimed late in a long batch is no longer born stale and re-claimed by a concurrent drain while it is still running.
- Order import matches line SKUs trimmed and case-insensitively (never when two IMS SKUs differ only by case, which is left unbound and logged), falls back to the WooCommerce id (a variation line only ever to its variation, never its variable parent), and logs each unmatched line once per order at import (with the order number) instead of silently reserving no stock.
- Admission-refusal recheck queue: only status-not-selected refusals expire after 30 days (status-not-mapped rows never do), status-only rows for deleted WooCommerce orders retire after three consecutive 404s (any other answer resets the count; guard and currency rows are never retired on a 404), and retirements no longer use up the 50-order live-read budget.
- Refund sync: over-total and over-quantity refusals are quarantined (operator-resolvable) instead of FAILED, so they stop being retried on every delivery.
