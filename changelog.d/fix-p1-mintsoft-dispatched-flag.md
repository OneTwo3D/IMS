### Fixed
- The Mintsoft align-down in-flight gate now uses the connector's own despatched decision (vendor status grouping or a despatch date), stored with each WMS status snapshot, instead of the status name alone. An order is released only on a successful read that explicitly says not despatched; an absent or failed decision holds.
- That read must also be newer than the Mintsoft stock read being aligned: a "not despatched" status taken before the stock read can no longer release an allocation that despatched in between (new hold reason `status_predates_stock_read`; the 45-minute freshness window is gone). The next status-sweep cycle re-evaluates.
- For a split Mintsoft order the stored decision now covers every part: despatched if any part is, not despatched only when every part was read and none is, unknown otherwise. Part 2 shipping before Part 1 no longer reads as not despatched.
