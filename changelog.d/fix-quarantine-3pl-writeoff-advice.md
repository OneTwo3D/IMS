### Condition check on returns: the 3PL write-off route follows the binding's stock mode (inventory)
Advice only; the switch `return_condition_check_enabled` stays off by default and nothing is posted differently.

- An unsellable unit at the 3PL (returns inbox restock, or a refund of units shipped from a WMS-bound warehouse) is still refused; the refusal now gives the write-off route of the binding that is known when it fires (the inbox row's warehouse, or the bound warehouse the refunded units shipped from). **Align To WMS:** restock as Sellable, the 3PL writes the unit off in Mintsoft and a later stock sync's align-down books it under the binding's align-down reason; no IMS stock adjustment (the next sync would book it back as a gain). **Notification only / disabled:** a real write-off in Mintsoft (no longer "or hold it out of sellable stock") and an IMS stock adjustment. With no binding known (for example only a synced push link), both routes are given. The inbox restock dialog shows the same advice for the item's warehouse.
- The refusal for a quarantine expected warehouse with returns in transit on now says plainly that, with both switches on, an unsellable return is never quarantined: it is restocked as Sellable when the parcel arrives and then written off.
- help-docs: the write-off is valued at FIFO (the warehouse's oldest open layers), not at the returned unit's own layer.
- **Review round 1.** "Align To WMS" advice is given only when align-down can actually run (binding and connection active, the connector enabled, alignment confirmed, an active align-down reason with an account, discrepancy thresholds set, the inventory account mapped where required); otherwise a new route says to write the unit off in Mintsoft and adjust IMS by hand (which clears the discrepancy), naming what blocks align-down. Inactive bindings or connections count as nothing aligning. The aligned advice notes that align-down can still hold a difference and points to the discrepancy list, explains that an extra IMS adjustment would be booked back as a stock gain, says the sync acts once it has seen the same difference twice, adds "or confirm Mintsoft does not count it", and asks for the write-off promptly. The restock dialog shows the route the server computes (one reader, `loadWmsWriteOffRoute`).
- **Review round 2.** The aligned route also needs the warehouse system's stock-alignment cron to be enabled (align-down runs only from it); with it off the advice is the manual route ("its stock sync is not scheduled"). The Mintsoft dashboard computes the routes only while the switch is on, in one batch over the bindings it already read, and falls back to "unknown" if a read fails. The returns-inbox route is read after the restock transaction rolls back.
