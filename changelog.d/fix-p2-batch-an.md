
### Fixes (P2 batch AN)

- **WooCommerce stock queue: a switched-off stock push no longer dead-letters its jobs.** When "Push stock levels to WooCommerce" is off, a queued stock push is kept and offered again later without spending an attempt, instead of burning its attempts until it lands in the dead-letter list.
- **CSV imports refuse a damaged file.** A row with a different number of cells from the header, or a quote in the middle of an unquoted cell, now refuses the whole file with the line numbers (nothing is imported), instead of shifting values into the wrong columns. A SKU, supplier name or order key that starts with `#` is imported as data; only a row whose FIRST cell starts with `# ` (such as `# REQUIRED`) is skipped, and the import result tells you when such a row is not the template's guidance row or an export's metadata. A space before an opening quote (`a, "b,c"`) is still fine; a stray quote or text after a closing quote refuses the file. Only the importers that already refuse damaged files (products, adjustments, opening stock, transfers, sales orders, purchase orders, suppliers, contacts) read this way; the WooCommerce import, Mintsoft bulk product data, the products round-trip and first-load keep the original lenient reading, unchanged.
- **Reconciliation pack, VAT (R12): months are London months.** IMS sales VAT and WooCommerce orders are bucketed by the London month, the calendar the Xero invoice dates use, so a BST month-end order no longer shows as a difference in two months. The population boundary is tested from London midnight. Transitional: for September and October 2026 Xero invoices were dated by UTC day, so a month-end order created 23:00 to 23:59 UTC can show as a difference in both months until those months leave the window.
- **Mintsoft alignment confirmation.** A dry run counts as evidence for confirming live corrections only if it ran under the warehouse binding's current write-off thresholds. Dry runs recorded before this change are not matched; run one fresh dry run.
- **Transfers: cancelling a dispatch.** The cancel is refused when units were actually received on the transfer's ASN, or a receipt event is still pending, retrying or awaiting review. A zero-quantity booked-in recheck no longer blocks it, and the refusal message names the way forward. The "ask the warehouse to cancel" notice no longer names placeholder ASNs that never reached the warehouse. An ASN closed by a dispatch cancel is no longer counted as incoming stock.
