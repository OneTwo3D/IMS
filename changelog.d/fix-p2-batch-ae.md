### Sales credit notes and invoices: allocation, invoice numbers, credit-note history VAT, refund VAT fence (sales / accounting)

- **New, OFF by default: apply a posted sales credit note to its Xero invoice.** With `xero_sales_credit_note_allocation_enabled` set to `true`, a credit note that has just posted as Authorised is allocated to the order's invoice (capped at what the credit note has left and the invoice still owes). Only an order with no receipt of any kind (none recorded, none queued, never marked paid) is allocated, because IMS cannot tell a refund paid back in cash from one meant to settle the invoice; every other order is left as before. Best effort, after the credit note's success is recorded: a refusal is a warning on the order (nothing due or receipts present is only an info line) and never fails the credit note. With the setting off nothing changes. Posting of the refund cash-out (paying the customer back) is not part of this change.
- **Fixed: generating an invoice number for an order whose invoice was already queued minted a second number that the accounting sync later overwrote.** The order now takes the number the queued (or posted, and still linked) invoice carries; the number of a deleted or voided invoice is never reused; with nothing queued a number is minted as before. No posting key changes.
- **Fixed: the credit-note history recomputed VAT and gross from the current tax table, so editing a tax mapping changed what a posted credit note showed.** Each refund line now records its VAT rate when the refund is created (new nullable column `posted_tax_rate`, additive, no backfill) and the history shows that. Older refunds, which have none stored, are still priced from the table and marked "estimated" (with the approximate sign) in the credit-note history.
- **Fixed: the refund VAT fence skipped the server-added order-discount reversal on public refunds.** The reversal is now refused when it would post at a rate other than the order's header rate, with the reason shown. An order whose default tax code can no longer be priced is not refused here (it is left to the later checks, as before).
