### Mintsoft archive `--execute`: proof the bridge is retired in the target, and harder tests (first-load)
- `first-load:mintsoft-archive --execute` now also refuses unless the TARGET installation holds a fresh `bridge-units-masked` writer attestation (generated within 24 hours) that `writers:check` would pass for step M: units masked and inactive, the report generated and recorded at or after `MINTSOFT_WRITES_LIVE_FROM`, the last trigger before it. Step M being live in the env file was not proof: stage carries those variables during its stage proof while the production plugin and bridge still sync, and an M rollback resumes the bridge. The attestation is read in the same READ ONLY transaction as the import proof and recorded with every write (`retirementEvidence`). Record it with `npm run writers:attest -- --kind bridge-units-masked` before the run.
- The command refuses a shell that exports `DATABASE_SESSION_LOCK_URL`, as it already refused an env file that sets it: the override would move the run's session and lock off the env file's database.
- A repeated stock row for the product (a SKU spelled in another case) is now reported as a repeat.
- New tests cover each write-path guard (bundle or discontinued flag absent or null, another product id in the answer, a stock row of another warehouse, client or SKU, a repeated or negative row, a 200 without a `Success` boolean or with a non-JSON body, a verified write that cannot be recorded, a switch re-read that fails, a duplicate warehouse, a stock row only in an unconfigured warehouse), the target connection's lock, and the script's env wiring. The DB-path census now also finds files that build a client through the session-lock factory.
