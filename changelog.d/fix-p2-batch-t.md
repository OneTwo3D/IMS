### WooCommerce outbound stock and product push (fixes)

- **Fixed: a long stock push can no longer write an older, higher figure over a newer, lower one.** Each batch now re-reads current availability for its own products just before it is sent and only ever lowers the figure, and the read and the send run one batch at a time within the server.
- **Fixed: a change to a component now re-pushes every kit above it, at any depth.** A kit inside a kit (a gift box holding a kit holding the component) was left stale in WooCommerce until the daily reconcile.
- **Fixed: variations beyond the first 100 of a parent now receive stock.** Looking up a variation WooCommerce id after a cache reset read only page 1.
- **Fixed: a failed IMS-to-WooCommerce product push (price, name, status) is recorded and retried safely.** A failure before WooCommerce accepted the write (a network error, a timeout, a 5xx) leaves one open FAILED Product row in the WooCommerce sync log (never two for a product), and the reconcile cron pushes the product again with a per-product backoff of 1 hour, 2 hours, 4 hours and so on, for up to 7 days, closing the row on success. A rejection that can never succeed (a 4xx answer to the PUT, a product with no SKU, a variant with no parent mapping) is recorded as a permanent FAILED row at once and not retried. Retries run after the stock queue and the stock reconcile, with 3 seconds of the 20 second request budget reserved for them so they run on every pass, each retry is cut off at the budget,  and the product due longest goes first. A failure AFTER WooCommerce accepted the write (the MPN not stored, the old GTIN not cleared) is recorded as a permanent FAILED row and is never sent again, so it cannot overwrite store-side edits. Pushes that settings or the outbound hold skip are not recorded.
- **Fixed: a variable parent the store cannot list in full no longer holds the daily stock reconcile.** A parent with more than 2,000 variations is skipped for that pass and reported in the activity log (`stock_sync_parent_skipped`); the reconcile window advances. A one-off variation page or network error is NOT skipped: it stays an error, so a queued stock job is retried and the window is held, exactly as before. Each parent's variation list is now read once per run, not once per 100 variants.
- **Fixed: a database error while a stock batch re-reads current stock no longer aborts the run.** The batch is sent as it was (unclamped) and the error is logged. A figure the re-read lowers to 0 now also gets its back-in-stock date, as a product that was at 0 already does.
- **Unchanged by design:** the re-read-and-send lock covers one server process only, and the stock figure is still only ever lowered by the re-read, never raised.
