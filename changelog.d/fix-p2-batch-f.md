### Backups: step-up for dump, upload and target settings; optional encryption before upload (security)

- **Fixed: a plain admin session could dump the whole database and send it off-site.** `POST /api/backup/create` and `POST /api/backup/upload-remote` now require a fresh sign-in (step-up), like restore and delete. The Backup screen prompts "Confirm it's you" and retries.
- **Fixed: the backup target could be repointed without step-up.** The S3/SFTP target settings are saved by a new fresh-auth-gated action and are no longer writable through the generic settings writer. Endpoint/host values pointing at loopback, link-local or metadata addresses are refused, and changing the S3 endpoint/bucket or the SFTP host/port/user requires re-entering the credential in the same save, so a stored secret is never sent to a new destination.
- **Added: Encrypt backups before upload** (Settings > Backup & Restore > Storage, **off by default**). Encrypts the SQL with AES-256-GCM before it goes to S3/SFTP and stores it as `.sql.enc`. The key comes from `BACKUP_ENCRYPTION_KEY` (or `SETTINGS_ENCRYPTION_KEY`) in the server environment, never from the database or beside the backup. Decrypt with `scripts/decrypt-backup.ts`; see `docs/backup-restore.md`.
