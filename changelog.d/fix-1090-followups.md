### Follow-ups to the VAT document-date change: invoice updates never fall back to today, producer-hold readiness check, shipping VAT row, timeline order (finance)

- **Fixed: an update of a posted sales invoice no longer falls back to today's date.** An order that has a Xero invoice id but no `invoicedAt` (a back-reference repair that could not recover the date, or the release-claim script) used to be re-dated to the day of the edit. The update now reads the date from the payload of the SALES_INVOICE row that posted the invoice first, then the storefront creation day, then the stored stamp, and is REFUSED with a visible reason (nothing saved) when none is readable. Never today's date. The payload read is declared as a shadow reader (`scripts/shadow-reader-declarations.ts`). Legacy manual orders whose `invoicedAt` holds the post instant no longer move by a day.
- **Added: `npm run preflight:production` fails (check `producer-hold-xero`) when the ownership map says Xeroom owns sales invoices and credit notes in the current phase and `PRODUCER_HOLD_ENFORCED_DESTINATIONS` does not name `xero` (or `all`).** The claim "no Xero write changes" holds only while that hold is enforced; stage sets it, a reinstalled production might not. The rollout-readiness gate carries the preflight verdict. Documented in `docs/installation.md` ("Producer hold readiness"), the switchover runbook (global gates, step X preconditions), `.env.example` and `docs/agent/env-vars.md`. A production environment file without the variable now FAILS the preflight until it is set.
- **Fixed: the VAT report's shipping row has its own key and label.** Shipping VAT no longer lands on the "No tax rate" 0% row of the same jurisdiction; shipping refund lines net against the shipping row. The row is documented as a residual (order tax less line tax: shipping VAT plus order-level discount VAT and rounding) and is not clamped; a notice counts orders where it comes out negative. The report notice also says manual orders whose invoice number IMS minted but which Xeroom posts are reported on the mint day. The shipping query now reads orders in pages and folds them into sums, so a busy quarter no longer counts every order and its lines toward the source row limit.
- **Fixed: on the customer timeline an invoice dated the day the order was placed sorts after the order placed** (it is shown at the order's own time on that day).
- **Changed: a post that is delayed stamps `invoicedAt` from the payload date; effect on reports.** A WooCommerce order posted days after creation (held or on hold) has `invoicedAt` = the storefront creation day, so revenue, Currency Summary and AR place it earlier than before, and an already-reviewed period can gain rows when a late post lands. This matches Xero.
- **Tests:** the source-text pins are replaced by behaviour tests (`originalSalesInvoiceDay`, `postedInvoicedAt`, a database-tier test that reads the payload date and runs a credit note twice). Stale comments on the reconciliation pack's VAT reader and `BackReferenceParams` corrected.
- **Changed (review round 1):** the unknown-original-date refusal applies only when the update would really be sent. Under the enforced Xero hold the update is recorded as a shadow with today's date and the payload flagged `dateUnknown` (an activity-log warning is written) and the edit goes through. The refusal has its own message. The CI `preflight-production` job sets `PRODUCER_HOLD_ENFORCED_DESTINATIONS=all`. Kind-less legacy refund lines follow the legacy rule (product: sale, negative: discount, else shipping), so only true shipping refunds net against the shipping row. A misspelled hold value passes the preflight with a warning that it holds every destination.
