### Sales orders now show an Invoicing state (Not / Partially / Fully invoiced), separate from the order status (sales / UI)

- **New: an invoicing state on every sales order, orthogonal to the status, like the refund state.** The order detail page shows a **Not invoiced / Partially invoiced / Fully invoiced** badge beside the status, the sales order list has an **Invoicing** filter (it combines with the status filter and, once picked, includes Completed and Delivered orders), and the sales order CSV export gains an `invoicingState` column at the end. A cancelled order keeps the invoicing state it had. Order statuses, the WooCommerce status mapping and the Mintsoft logic are unchanged.
- **How it is derived (never set by hand).** An order is invoiced when IMS has queued or posted a sales invoice for it (a queued invoice counts at once), when the accounting invoice is linked to it, or, in the parallel phase, when the Xeroom invoice number is on a WooCommerce order. A failed invoice that reached nothing, one cancelled before posting, and a shadow recorded while writes are held do not count, so a voided invoice returns the order to Not invoiced. Credit notes and refunds never un-invoice. Partially invoiced means the invoice IMS holds covers fewer units than the order holds; an invoice IMS cannot read reads Fully invoiced. One helper (`lib/domain/sales/invoicing-state.ts`) is the only writer, called at every place that queues, fails, retires, settles, links or imports a sales invoice.
- **Existing orders.** Additive migration: a new `InvoicingState` enum and `sales_orders.invoicing_state` (default NOT_INVOICED). The migration sets FULLY_INVOICED on every existing order with invoice evidence (a linked accounting invoice, a queued or posted invoice row or one naming a document, or the incumbent's number on a WooCommerce order), so no stored value is wrong after the upgrade. A partially covered order is refined by `npm run sales:invoicing-state:recompute` (idempotent, `-- --dry-run` reports without writing) or by the next write to its invoice. Help document: Sales Orders.
