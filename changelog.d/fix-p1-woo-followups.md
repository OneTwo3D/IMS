### WooCommerce: resumable cancellation backfill, and a stock push that no longer trusts a missing reconcile cursor

- **Fixed: the cancellation backstop's first run could never finish on a large store.** The first run read every cancelled and trashed order in one go and saved its cursor only at the end, so a store whose history took longer than the request budget restarted the walk every hour. The first run is now a resumable backfill: each run reads a bounded number of pages (8 pages, 35 seconds at most), saves its position after every page that was read and applied cleanly, and continues from there next time. A failure holds the position (it is never skipped; the next run re-reads one page behind it). The normal cursor mode, with its overlap, starts only once both cancelled and trash have been read to the end, and is dated from when the backfill began.
- **Fixed: the stock push could oversell when the order reconcile had never run.** With no reconcile cursor the guard read only the last day of completed orders and still called the picture complete. A missing sweep cursor now means every completed order is read, under the same completeness proof as the open orders. If that read cannot be proven (a very large history, or no total from WooCommerce) the push is limited to forced-zero products and says why.
