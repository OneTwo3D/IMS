### Orders (owner decisions 2026-11-18)

- **WooCommerce order amendments, write step behind `wc_order_amendment_write_enabled` (off by default).** Latest edit wins per line (an IMS edit stands unless WooCommerce changed that line after it). A reduction on a PAID order is recorded through the refund path (credit note, stock released, shop-refund task) and never edits the paid amount; only unshipped units. Once picking has started (IMS status, or the warehouse order no longer open for changes) IMS sends nothing and raises the new operator task `WC_EDIT_AFTER_PICKING`. Unpaid orders, increases, prices, added items, shipping, discount and tax are still only reported; IMS-to-WooCommerce line writeback is not built. New nullable column `wc_order_divergences.amendment_claim` makes one set of differences act once.
- **Back-in-stock date is supplier ETA + 3 days (configurable).** `wc_back_in_stock_date_buffer_days` (default 3, 0 shows the raw date), in Sync settings. A late supplier date is still dropped before the buffer is added. Only matters while *Include estimated back-in-stock date* is on.
- **Mintsoft variant names keep the plugin format `Parent (a, b)`** (with product parity on), so nothing in Mintsoft is renamed at cutover. Before, IMS sent `Parent — a / b`.
- **Refund of returned, shipped units: ask the warehouse for the remainder.** The warehouse push still subtracts the gross refund (quantity unchanged). When that leaves the warehouse order short of what IMS still owes (ordered 10, 8 shipped, 2 returned and refunded), the push sweep raises one operator task `REFUND_REMAINDER_DUE` with the SKU and quantity. Behind `wms_refund_remainder_task_enabled` (off by default). Migrations are additive: two operator-task reasons and one nullable column.

- **Review fixes (round 1).** A paid reduction is no longer refunded once picking has started: the warehouse gate is asked before any refund, and an unreadable gate fails closed (task, no refund). The amendment step runs under a per-order lock and re-reads the refunded quantities; the refund transaction re-checks the reduction cap, so racing deliveries refund once. Stale deliveries are ignored, the latest-edit rule uses the baseline only, a reduce-then-restore raises a task, IMS lines sharing a WooCommerce item are added up, and an order-level discount is left for a person. The refund-remainder sweep pages with a cursor and dedupes per order and SKU. Mintsoft variant names keep values containing " / " whole.
