
### Fixes (reconciliation pack, warehouse reconcile, writers check, first load, product content, Mintsoft)

- **Reconciliation pack: a failing item must list a finding.** A report item that says `fail` with `DIFFERENCES` but lists nothing is now refused when the report is built or read. A carried difference with more later stamps than the settling window is refused, so repeated stamps cannot settle a difference early.
- **Warehouse reconcile while writes are held: only shadowed orders are closed.** An open "not pushed" finding is closed by the hold only when IMS holds a durable held-create record for that order. A finding raised during a live period (the push cron really stopped) stays open.
- **writers:check: the journal capability follows the queue gate.** `xero.inventory.journals` is derived from every sync type in its ownership row and the queue's own per-type switches; STOCK_IN_TRANSIT, UNEARNED_REV_REVERSAL and ALLOCATION_REVERSAL have no switch and post whenever Xero sync is on, so the report no longer understates what IMS can write.
- **First-load apply: a run-wide lease.** Resuming a RUNNING run now takes a lock held for the whole run (a second runner is refused instead of advancing the journal under the first), and the per-call guard stops a runner whose journal version was moved by another.
- **Product content sync.** A variation's single `image` is imported; an HTTP 200 with `Success: false` is no longer recorded as sent; two runs cannot leave a stored hash Mintsoft does not hold; variation content is read once per parent; the run summary counts shadowed fields when a picture was sent. (The ImageURL partial POST stays as it is until a controlled update has been checked.)
- **Mintsoft: shipping VAT, behind `mintsoft_send_shipping_vat` (off by default).** With the setting `true`, `ShippingTotalVat` carries the shipping VAT (order tax minus line tax). Off, the payload is unchanged.
- **Warehouse reconcile while writes are held: an unreadable shadow record makes the run PARTIAL.** A held-create shadow record that cannot be read still leaves its finding open, and is now also counted into the sweep's error counter (was logged only), so the run reports PARTIAL instead of a clean SUCCEEDED.
