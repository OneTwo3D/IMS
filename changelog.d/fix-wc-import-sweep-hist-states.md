### WooCommerce order import: stable sweep paging, finished orders carry no stock (woocommerce)
- The order poll and reconcile now page by keyset on modification time (`orderby=modified`, position moved by the last order's modified time, a 65-minute overlap and an offset read of any window too dense to advance) with explicit GMT filters (`dates_are_gmt=true`, suffix-less GMT values). An order that leaves the selected statuses mid-walk no longer shifts the offsets and skips another order, and an order modified after its page was read is read again. The cancellation backstop's window filter uses the same GMT form. Orders already handled at the same modified time are not handled again within a run.
- An order first seen as `completed` (or mapped to Shipped / Completed / Delivered) is recorded in that status with no stock reservation, no shipment and no stock movement, and is never a warehouse push candidate; an order first seen as `refunded` is recorded as Cancelled with no demand and no invoice owed. Each writes an INFO activity entry (`order_imported_post_dispatch_no_stock`, `order_imported_refunded_as_cancelled`).
- Already in place before this change (verified, no code change): the sweep position is the run's START time less a 2-minute overlap, the initial import stamps its start, and webhooks never advance the poll cursor.
