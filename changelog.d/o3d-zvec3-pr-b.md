### Switchover: evidence sources, companion-plugin probe, gap list, rollback hand-back, withdrawal-outcome and TrackShip batch writers (cutover)
Everything here is inert until its switchover step is live: a new setting that defaults off, a command run by hand, or a read that is only made once the step's live-from instant is set. Nothing is deployed to the store by this change; the companion plugin 1.5.0 needs the owner's explicit OK to install.

- **Companion plugin 1.5.0 (not deployed).** Two new signed routes. `GET /wp-json/oti/v1/incumbents` is a read-only probe of whether the legacy bridge plugin (exact slug `wc-mintsoft-sync`) and Xeroom's order note are still writing: whether the bridge's REST routes are registered (read from `rest_get_server()->get_routes()`, so it holds however the plugin is loaded), its `order_sync_enabled` switch, its product webhook, pending `wc_mintsoft_run_product_sync` jobs, the newest `_mintsoft_*` time it stamped on an order, and Xeroom's note switch `o3d_xeroom_order_note_off`. It is signed over method, path, timestamp and a single-use nonce inside a 60 second window. `POST /wp-json/oti/v1/order/{id}/withdrawal-outcome` writes the outcome of a customer's EU withdrawal request (an order note, once per outcome key, and the rejection of a request made after despatch).
- **Probe client** (`lib/connectors/woocommerce/incumbent-plugins.ts`): one signed GET through the helper-read gate; the reply is reduced to a closed shape and judged by closed violation codes. A field the plugin could not read is a violation of its own, never taken as fine.
- **Withdrawal outcome writer, behind `wc_withdrawal_outcome_enabled` (default off).** Takes over from the bridge's `/wdraw-outcome` at step M. Held until step M is live; a failure is logged and never fails the withdrawal handling. `writers:check` now requires this switch to be on from step M (the no-writer finding).
- **TrackShip batch reconcile.** The `shopping-webhook-inbox` job's TrackShip sweep now scans in passes of 50 (the bridge's `/trackship/reconcile` took 50 a call) until it has caught up, up to 4 passes a tick, instead of 25 a tick. Still off unless `trackship_refire_enabled` is `true`.
- **The invoice note has its own switch, `wc_invoice_note_enabled` (default off).** It used to follow `xero_sync_sales_invoice`, which defaults on, so IMS's note would have joined Xeroom's as soon as the Xero flow ran. With it off no note is queued and a queued one is not sent. `writers:check` uses the new switch.
- **`npm run switchover:gaps -- --step mintsoft`** lists G_create (paid before S, no Mintsoft link) and G_despatch (despatched before S, storefront not completed), read only. `-- --take-over <orderId>` closes one order and reads before it writes: a G_create order is adopted from Mintsoft (a link in PENDING_VERIFY; nothing is sent to Mintsoft; an order Mintsoft does not hold is refused, IMS never creates a pre-S order), a G_despatch order has the storefront read first and then the ordinary completion queued. Dry run by default, `--apply` writes.
- **Mintsoft foreign-order reader** (`lib/connectors/mintsoft/foreign-orders.ts`): counts orders of the client created at or after S with no IMS link. Fail closed on a row of another client, a truncated list or a read error; a row with no readable creation time is counted.
- **`npm run switchover:hand-back`** (rollback of step M): writes `_mintsoft_order_id` and `_mintsoft_order_number` onto the open storefront orders IMS created in Mintsoft, so the resumed bridge adopts them. Reads each order first, never overwrites a different value, dry run by default, `--apply` writes.
- **Stock-drift observer** (`npm run switchover:stock-drift`, hourly from the host scheduler once the Qoblex stock push is stopped): reads every managed-stock product and variation (GET only) and records changes that no order, refund or IMS push explains. New tables `wc_stock_snapshots`, `wc_stock_drift_events` and `wc_stock_drift_runs` (additive migration).
- **`writers:check` evidence sources.** BRIDGE_PROBE, MINTSOFT_FOREIGN_ORDER, XEROOM_NOTE (the probe's option) and STOCK_DRIFT no longer answer "not built". Each is asked only once its step's live-from instant is set (a new `not-due` reading before that), so the daily P1 check never depends on the plugin being deployed; a probe that does not answer is `not-probed` and fails. The bridge host's systemd attestation stays a `writers:attest` input and still reads "not built".
