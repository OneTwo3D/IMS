### IMS now mirrors WooCommerce's IOSS number, delivery term, duty/tax components, customs values and US tariff codes (backend / sync / sales / warehouse)

- **New: WooCommerce's duty and tax results are copied onto IMS and never recalculated (owner decision D5).** The order import stores the IOSS number (`_o3d_ioss_number`), the delivery term (`_o3d_delivery_term`: IOSS_DDP, DDP or DDU_DAP) and each order line's customs value override (`_wc_label_customs_unit_value`), beside the duty / import VAT / handling components it already kept. The product import stores the US HS code (`pa_us_hs_code`) and the per-destination codes (`_dutify_hs_codes`) in their own fields, separate from the IMS-owned HS code, which is never written from them. Missing or unusable values stay empty.
- **Changed: these values now follow WooCommerce on every order update.** The duty / import VAT / handling components were previously written only when the order was created; they now resync like the rest, and a value WooCommerce removes is cleared. Lines and invoices are still not rebuilt by an update.
- **New: read-only Duty and tax panel on the order page,** labelled "from WooCommerce".
- **New: setting `mintsoft_send_ioss_number` (Integrations > Mintsoft, default OFF).** When on, the Mintsoft order create push sends `IOSSNumber` for orders that carry one. With it off the push is byte-identical to before. Mintsoft is live, so nothing changes until it is switched on.
- Additive migration `20261117090000_mirror_woo_duty_tax` (nullable columns on `sales_orders`, `sales_order_lines` and `products`; no backfill, the next import or update fills them). Help documents: Sales, WooCommerce, Warehouse (Mintsoft); `docs/mintsoft.md`.
