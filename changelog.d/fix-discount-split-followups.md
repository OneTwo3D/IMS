### Order discount VAT per rate: follow-ups before the switch can be turned on (sales, Xero, refunds, reconciliation pack)

All of this applies only to orders priced with `sales_order_discount_tax_apportion_enabled` on, which stays OFF. With it off nothing a new order writes or queues changes (the write-model golden file is untouched).

- A discounted order whose lines with no tax rate have no accounting tax code to be posted on (no order default VAT rate, or one with no code) is refused again, with a message saying what to fix, when it is created as a live order, when a confirmed order is edited and when a draft is finalised. Before, it saved and its invoice was then refused at the sync processor ("NOTHING WAS SENT"). A draft, including every CSV import, still saves; its finalisation is checked against the tax rates as they are then. The check uses the invoice's own code derivation, and the invoice build refuses the same order as a backstop.
- The tax code of each group of the split now comes from one shared function for the invoice's discount parts and the refund's per-rate discount reversal. The refund now falls back to the order default rate's code for a group with no code of its own, as the invoice already did, so the credit note reverses the discount on the code the invoice posted it on.
- Reconciliation pack R12: a split entry so small that the invoice posts no discount line for it (it rounds to no positive penny) is no longer taken off the IMS side.
- Docs: the help text and the installation guide no longer say the no-rate group is "0% / no VAT" (its rate is the order's header VAT percentage); the R12 figures paragraph describes the split. The two earlier fragments now say that refunds, invoice updates and the VAT report follow any order that already carries a stored split, so "unchanged with the switch off" holds only while no order has one.
