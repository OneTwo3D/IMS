### Credit-note PDF: each line's VAT comes from its own refund line, and figures use the currency's decimals

- **Fixed: a posted credit note's PDF no longer matches lines by description.** A refund line with an empty description posts as "Refund line", missed the match and printed the order's default rate, so a zero-rated line on a 20% order showed VAT its tax code does not carry; lines sharing a description could swap rates. A newly queued credit note now records, on each posted line, the refund line it belongs to, and the rate of the tax code it posts under. The PDF prints that rate (never the source's rounded VAT), with VAT rounded per line to the currency's minor unit as the ledger does, so a 0.13 net line at 20% prints 0.03. Both markers are never sent to the accounting system.
- **Changed: a credit note queued before this cannot be printed with VAT.** Its lines carry no recorded tax-code rate, so the PDF request now returns an explanation instead of a guessed rate. Use the credit note in your accounting system for those.
- **Fixed: credit-note PDF figures use the currency's own decimals.** Three- and four-decimal currencies (KWD, CLF, UYW) were rounded to two places, so a 0.0001 credit printed 0.00. Rows, Rounding row, totals and printed text now use the currency's precision, and the totals equal what the credit note posts.
- **Fixed: the PDF now shows the lines as Xero keeps them.** Xero rounds each unit price to four decimals and IMS posts the difference as a separate untaxed **Rounding adjustment** line. The PDF now prints each line at the four-decimal price with VAT per line, and that adjustment as its own row, so its total equals the credit note posted (for example 300 x 0.33342 at 20% prints a 100.02 line, 20.00 VAT, a 0.02 Rounding adjustment and 120.04). A credit note whose total cannot be reproduced that way is refused with an explanation.
