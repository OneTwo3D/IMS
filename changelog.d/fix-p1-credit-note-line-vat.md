### Credit-note PDF: each line's VAT comes from its own refund line, and figures use the currency's decimals

- **Fixed: a posted credit note's PDF no longer matches lines by description.** A refund line with an empty description posts as "Refund line", missed the match and printed the order's default rate, so a zero-rated line on a 20% order showed VAT its tax code does not carry; lines sharing a description could swap rates. A newly queued credit note now records, on each posted line, the refund line it belongs to, and the PDF reads that refund line's recorded VAT rate. The marker is never sent to the accounting system.
- **Changed: a credit note queued before this cannot be printed with VAT.** Its lines cannot be tied to refund lines, so the PDF request now returns an explanation instead of a guessed rate. Use the credit note in your accounting system for those.
- **Fixed: credit-note PDF figures use the currency's own decimals.** Three- and four-decimal currencies (KWD, CLF, UYW) were rounded to two places, so a 0.0001 credit printed 0.00. Rows, Rounding row, totals and printed text now use the currency's precision, and the totals equal what the credit note posts.
