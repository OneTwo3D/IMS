### Refund delete, Xero document delete and invoice-document fetch: race fixes before the switches go on (sales, accounting)

All three features stay off by default (`refund_delete_enabled`, `xero_document_delete_enabled`, `invoice_documents_lazy_fetch_enabled`); each change only makes IMS refuse or wait where it used to go ahead.

- **Refund delete, the credit note void.** The void worker now locks the order, the returned stock and the cost layers the return created, checks the delete again, and only then sends the void to Xero; the IMS unwind commits under the same locks. If the returned stock was used while the void waited (or the delete is no longer allowed), nothing is sent and the refund and its credit note both stand, with the reason on the failed entry. Before, Xero could lose the credit note while IMS kept the refund.
- **Refund delete, the void last (review round 1).** Under the locks the worker now runs the whole IMS unwind first and sends the void as the last step before the commit; lock waits are capped at 5 s, the void is a bounded Xero call (no in-request sleeps or retries, 15 s per call) and is not started unless it fits in the transaction's remaining time. When an earlier attempt may have reached Xero, the credit note is read before anything is reported; voided in Xero with the unwind refused raises the new operator task `REFUND_DELETE_VOIDED_NOT_UNWOUND` (additive migration `20261122130000_refund_delete_voided_task`).
- **Refund delete, re-reserving the order.** A delete completed by the void worker now re-reserves the order (PROCESSING or ALLOCATED, re-checked under the order lock, never once a shipment exists), as the order page already did, and logs a warning when the allocation fails (a declined or skipped one is silent).
- **Xero document delete, the pending-delete fence.** A refund, marking an order paid, a bill edit, a bill payment and a supplier credit note now check for a pending delete inside their transaction, after the lock the delete request takes, so one racing the request is refused instead of attaching to a document Xero is about to remove. A supplier return that would credit a bill being deleted is refused too.
- **Xero document delete, lock order.** The bill delete's request and completion, and a bill edit, take the purchase order before the bill, as the supplier return does, removing a deadlock between completion and a return.
- **Invoice-document fetch, the shared Xero budget.** Xero's `X-DayLimit-Remaining` is shared between workers (new table `xero_day_limit_observations`, additive migration `20261122120000_xero_day_limit_observation`); the sweep reads the lowest fresh figure, and an unknown budget counts as low (`lazyDeferred: ledger-budget-unknown`). A customer request that has waited 14 days without a fetch is handed to a person (`lazyAgedOut`), so a budget that stays low cannot keep the waiting cap full.
